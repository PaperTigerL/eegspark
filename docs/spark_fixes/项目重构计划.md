# Py4J和Spark连接修复模块重构计划

## 问题描述

当前项目中与Py4J连接和Spark相关的文件散布在src目录的根部，缺乏合理的组织结构，导致以下问题：

1. 代码组织混乱，难以维护
2. 导入路径不一致，可能导致执行错误
3. 测试文件与实现文件混在一起
4. 文档不足，缺乏使用说明

## 重构目标

1. 创建清晰的目录结构，按功能分类文件
2. 统一导入路径，确保代码可以正确执行
3. 分离测试文件和实现文件
4. 添加必要的文档说明

## 文件重组计划

### 1. 工具类文件移动

将修复工具类文件移动到 `utils/spark_fixes` 目录：

- `fix_ivy_config.py` → `utils/spark_fixes/ivy_config.py`
- `docker_py4j_fix.py` → `utils/spark_fixes/docker_py4j_fix.py`

### 2. 测试文件移动

将测试文件移动到 `tests/spark` 目录：

- `test_py4j_connection.py` → `tests/spark/test_py4j_connection.py`
- `test_ivy_config.py` → `tests/spark/test_ivy_config.py`
- `test_sparkcontext.py` → `tests/spark/test_sparkcontext.py`
- `test_visualization_py4j_fix.py` → `tests/spark/test_visualization_py4j_fix.py`
- `docker_py4j_test.py` → `tests/spark/docker_py4j_test.py`

### 3. 文档文件移动

将文档文件移动到 `docs/spark_fixes` 目录：

- `DOCKER_PY4J_FIX_README.md` → `docs/spark_fixes/docker_py4j_fix.md`

- `PY4J_CONNECTION_FIX.md` → `docs/spark_fixes/py4j_connection_fix.md`
