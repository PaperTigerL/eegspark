# 模拟器实验前期计划
## 一、实验背景与目标
本次实验旨在构建一个基于 Docker 容器的模拟器环境，通过模拟实时数据生成、传输以及后续由 Spark 网络进行数据处理加工和计算的完整流程，确保整个数据处理链路的稳定性与可靠性。

## 二、实验架构概述
1. **数据生成层**：通过设置两个 Docker 容器，分别读取挂载不同的 sub 数据，模拟不同实验者的实时数据生成工作。
2. **数据传输层**：利用特定的脚本文件作为模拟器容器的发送脚本，负责将生成的数据发送至 Spark 网络。
3. **数据处理层**：Spark 网络接收来自模拟器容器发送的数据，并进行后续的数据处理、加工和计算等工作。

## 三、实验步骤
1. **Windows 模拟环境搭建**
    - 在 Windows 操作系统上部署必要的工具和环境，以模拟 Docker 容器运行环境及数据传输流程。
    - 安装 Docker 桌面版（Docker Desktop for Windows），确保其正常运行并进行基础配置。
2. **数据准备**
    - 准备两份不同的 sub 数据，分别用于挂载到两个 Docker 容器，模拟不同实验者的实时数据。
    - 确保数据格式符合后续模拟器容器读取及 Spark 网络处理的要求。
3. **模拟器容器脚本开发与配置**
    - 编写模拟器容器的发送脚本，该脚本需实现从挂载的 sub 数据中读取数据，并发送至 Spark 网络的功能。
    - 在脚本中配置正确的 Spark 网络地址及相关参数，确保数据能够准确无误地发送。
    - 在 Windows 模拟环境中对脚本进行初步调试，检查是否能正常读取数据并尝试发送。
4. **模拟读取与发送测试**
    - 在 Windows 模拟环境下，启动两个模拟的 Docker 容器，分别挂载准备好的不同 sub 数据。
    - 运行模拟器容器的发送脚本，观察数据是否能够从容器中正确读取，并成功发送至模拟的 Spark 网络。
    - 记录发送过程中出现的任何错误信息或异常情况，以便及时进行排查和修正。
5. **问题排查与优化**
    - 针对模拟读取与发送过程中出现的问题，如数据读取错误、发送失败等，进行详细的问题排查。
    - 根据排查结果，对模拟器容器脚本、数据格式或网络配置等进行相应的优化和调整。
    - 反复进行模拟读取与发送测试，直至数据能够稳定、准确地从模拟器容器发送至 Spark 网络，确保这一环节不存在明显问题。

## 四、预期结果
通过在 Windows 上进行模拟读取并发送的过程，成功实现从两个模拟的 Docker 容器中读取不同的 sub 数据，并稳定、准确地将数据发送至 Spark 网络，为后续在实际 Docker 容器环境及 Spark 网络中进行完整的实验奠定基础。
