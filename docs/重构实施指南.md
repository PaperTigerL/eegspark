# EEGSpark 项目重构实施指南

本文档提供了 EEGSpark 项目重构的具体实施步骤，帮助您按照计划逐步整理代码结构。

## 准备工作

在开始重构前，请确保：

1. **备份项目**：创建完整的项目备份，以防需要恢复
2. **了解项目结构**：阅读 `README.md` 和 `docs/重构计划.md` 文档，了解重构目标
3. **准备好开发环境**：确保您的开发环境可以正常运行项目

## 实施步骤

### 第一阶段：创建新目录结构

```bash
# 在项目根目录下执行以下命令

# 创建工具目录
mkdir -p src\utils\spark_fixes
mkdir -p src\utils\logging

# 创建测试目录
mkdir -p tests\unit
mkdir -p tests\integration

# 创建文档子目录
mkdir -p docs\design
mkdir -p docs\technical
mkdir -p docs\modules\processor
mkdir -p docs\modules\visualization

# 创建脚本目录
mkdir -p scripts\setup
mkdir -p scripts\docker

# 创建配置目录
mkdir -p config\spark
mkdir -p config\docker
mkdir -p config\logging

# 创建必要的 __init__.py 文件
type nul > src\utils\__init__.py
type nul > src\utils\spark_fixes\__init__.py
type nul > src\utils\logging\__init__.py
type nul > tests\__init__.py
type nul > tests\unit\__init__.py
type nul > tests\integration\__init__.py
```

### 第二阶段：移动修复工具文件

```bash
# 移动 Spark 连接和 Py4J 修复相关的文件
copy src\visualization\spark_connection_fix.py src\utils\spark_fixes\
copy src\docker_py4j_fix.py src\utils\spark_fixes\
copy src\fix_ivy_config.py src\utils\spark_fixes\
```

### 第三阶段：移动测试文件

```bash
# 移动测试文件到 tests\unit 目录
copy src\test_ivy_config.py tests\unit\
copy src\test_py4j_connection.py tests\unit\
copy src\test_sparkcontext.py tests\unit\
copy src\test_visualization_py4j_fix.py tests\unit\
```

### 第四阶段：整理文档文件

```bash
# 移动设计文档
# 注意：这些文件已经在 docs 目录中，只需要移动到子目录

# 移动技术文档
copy src\DOCKER_PY4J_FIX_README.md docs\technical\DOCKER_PY4J_FIX.md
copy src\IVY_FIX_README.md docs\technical\IVY_FIX.md
copy src\PY4J_CONNECTION_FIX.md docs\technical\PY4J_CONNECTION_FIX.md

# 移动模块文档
copy src\processor\README_async_source_localization.md docs\modules\processor\async_source_localization.md
copy src\visualization\README_PY4J_FIX.md docs\modules\visualization\PY4J_FIX.md
```

### 第五阶段：创建脚本目录

```bash
# 移动脚本文件
copy fix_docker_py4j.bat scripts\setup\
copy fix_docker_py4j.sh scripts\setup\
copy src\docker_entrypoint.sh scripts\docker\
```

### 第六阶段：更新导入路径

这一步需要手动编辑文件，更新导入路径。以下是需要修改的主要文件：

1. **更新 src/visualization/spark_connection_fix.py**

   将：
   ```python
   from fix_ivy_config import fix_ivy_repository_path
   ```
   
   改为：
   ```python
   from utils.spark_fixes.fix_ivy_config import fix_ivy_repository_path
   ```

2. **更新所有引用了修复工具的文件**

   搜索所有引用了 `fix_ivy_config`、`docker_py4j_fix` 和 `spark_connection_fix` 的文件，更新导入路径。

3. **更新测试文件**

   修改 `tests/unit/` 目录下所有测试文件中的导入路径。

### 第七阶段：优化模块组织

这一步需要根据 `docs/重构计划.md` 中的建议，进一步组织 `processor` 和 `visualization` 模块的文件结构。

```bash
# 为处理器模块创建子目录
mkdir -p src\processor\core
mkdir -p src\processor\analysis
mkdir -p src\processor\localization
mkdir -p src\processor\models

# 为可视化模块创建子目录
mkdir -p src\visualization\core
mkdir -p src\visualization\servers
mkdir -p src\visualization\visualizers

# 创建必要的 __init__.py 文件
type nul > src\processor\core\__init__.py
type nul > src\processor\analysis\__init__.py
type nul > src\processor\localization\__init__.py
type nul > src\processor\models\__init__.py
type nul > src\visualization\core\__init__.py
type nul > src\visualization\servers\__init__.py
type nul > src\visualization\visualizers\__init__.py
```

然后，按照计划移动文件到相应的子目录。

### 第八阶段：配置文件管理

```bash
# 创建配置文件示例
type nul > config\spark\spark-defaults.conf
type nul > config\logging\logging.conf

# 复制 docker-compose.yml 到配置目录
copy docker-compose.yml config\docker\
```

### 第九阶段：清理和测试

在完成上述步骤后，需要进行清理和测试：

1. **删除已移动的原始文件**（确保新位置的文件可以正常工作后）
2. **运行测试**，确保功能正常
3. **更新主 README.md**，反映新的项目结构

## 分阶段实施建议

为了降低风险，建议按照以下顺序分阶段实施：

1. 首先创建新的目录结构（第一阶段）
2. 移动并更新修复工具（第二阶段和第六阶段的相关部分）
3. 移动测试文件（第三阶段）
4. 整理文档文件（第四阶段）
5. 创建脚本目录（第五阶段）
6. 优化模块组织（第七阶段）
7. 配置文件管理（第八阶段）
8. 清理和测试（第九阶段）

每完成一个阶段，都应该进行测试，确保功能正常。

## 注意事项

1. **保持原有功能**：重构的目的是改善代码组织，不应改变功能
2. **逐步进行**：每次只改变一小部分，并进行测试
3. **使用版本控制**：每个重要步骤后提交代码，便于回滚
4. **更新文档**：随着重构的进行，及时更新文档

## 重构后的验证

完成重构后，应该进行以下验证：

1. **运行所有测试**，确保功能正常
2. **检查导入路径**，确保没有遗漏
3. **验证主要功能**，确保系统各部分正常工作
4. **更新所有文档**，反映新的项目结构

## 结论

按照本指南进行重构，可以使 EEGSpark 项目的代码结构更加清晰和有组织，提高代码的可维护性和可扩展性。重构是一个渐进的过程，应该谨慎进行，确保每一步都不破坏现有功能。
